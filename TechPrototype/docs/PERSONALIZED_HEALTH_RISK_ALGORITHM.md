# 安康助手个体化健康风险算法说明

> 当前实现版本：`hybrid-risk-v1`

## 1. 文档目的

本文说明安康助手 `hybrid-risk-v1` 混合风险算法的设计、实现方式、评分规则、
安全边界和测试方法。

该算法解决固定阈值模型的两个主要问题：

1. 指标尚未超过统一参考范围，但已经显著偏离用户个人规律时无法发现。
2. 单项指标变化不大，但多项指标同时异常或持续恶化时无法综合判断。

本功能用于日常健康管理提示，不用于疾病诊断，也不能替代医生判断。

## 2. 核心设计原则

系统采用“医学规则 + 个体统计模型”的混合结构：

```text
健康记录入库
  -> AFTER_COMMIT 发布 HealthRecordCreatedEvent
  -> 读取近 30 天个人历史数据
  -> 医学安全规则
  -> MAD 个体基线
  -> EWMA/CUSUM 趋势检测
  -> 收缩协方差马氏距离
  -> 数据可信度修正
  -> 风险分数与可解释原因
  -> HealthOps Event Mesh 状态流转
  -> SSE 推送 Flutter 风险弹窗
```

医学规则是安全底线，统计模型只能增加风险，不能降低医学红线已经确定的风险。

## 3. 代码结构

主要实现位于：

```text
TechPrototype/src/main/java/com/ankang/assistant/eventmesh/service/
├── RiskEngineService.java
├── AdaptiveRiskAnalyzer.java
└── AdaptiveRiskResult.java
```

职责如下：

| 类 | 职责 |
|---|---|
| `RiskEngineService` | 医学阈值、提醒上下文、总分融合和风险等级判定 |
| `AdaptiveRiskAnalyzer` | 个人基线、趋势、联合异常和可信度计算 |
| `AdaptiveRiskResult` | 返回个体算法分数、本次记录分数和解释原因 |
| `HealthEventProcessor` | 在事务提交后异步调用风险引擎并推送结果 |

## 4. 输入数据

算法直接使用 `health_record` 表中的数据，不需要单独训练模型。

当前支持以下个体化指标：

| 记录类型 | 特征 |
|---|---|
| `blood_pressure` | 收缩压、舒张压 |
| `heart_rate` | 心率 |
| `blood_glucose` | 血糖 |
| `weight` | 体重 |

每次评估读取：

- 近 30 天记录：构建个人基线、趋势和多指标历史模式。
- 近 24 小时每类最新记录：形成当前关联指标向量。
- 本次触发记录：始终作为主指标，即使用户补录的是较早测量时间。
- 当日服药提醒：作为风险上下文。

## 5. 医学规则层

医学规则沿用原有安全阈值，例如：

- 血压达到 `180/120 mmHg`：本次指标增加 60 分。
- 血压达到 `160/100 mmHg`：增加 45 分。
- 血压达到 `140/90 mmHg` 或低于 `90/60 mmHg`：增加 25 分。
- 心率高于 `120 bpm` 或低于 `50 bpm`：增加 40 分。
- 心率高于 `100 bpm` 或低于 `60 bpm`：增加 25 分。
- 血糖达到 `11.1 mmol/L`：增加 30 分。
- 血糖高于 `6.1 mmol/L` 或低于 `3.9 mmol/L`：增加 20 分。

这些分数不会被数据可信度折减。

## 6. MAD 个体基线

### 6.1 为什么使用 MAD

普通均值和标准差容易被错误录入或极端值拉偏。系统使用中位数和
MAD（Median Absolute Deviation）构建鲁棒基线：

```text
median = 历史数据中位数
MAD = median(|x_i - median|)
scale = max(1.4826 * MAD, 指标最小尺度)
robustZ = |本次值 - median| / scale
```

指标最小尺度用于处理长期数据完全相同、MAD 为零的情况：

| 特征 | 最小尺度 |
|---|---:|
| 收缩压 | 5 mmHg |
| 舒张压 | 4 mmHg |
| 心率 | 3 bpm |
| 血糖 | 0.30 mmol/L |
| 体重 | 0.50 kg |

### 6.2 时间分段

系统优先使用与本次测量处于同一时间段的历史记录：

- 清晨：05:00～11:59
- 白天：12:00～17:59
- 晚间：18:00～22:59
- 夜间：23:00～04:59

同一时间段不足 7 条时，回退到全部时间段的历史记录。

### 6.3 个人偏离评分

| Robust Z | 个体分数 |
|---|---:|
| `< 2.5` | 0 |
| `2.5～3.0` | 12 |
| `3.0～4.0` | 18 |
| `>= 4.0` | 24 |

示例解释：

```text
个体基线：心率为 96 bpm，个人基线约 66～75 bpm，偏离 4.2 MAD
```

因此，即使 `96 bpm` 尚未超过统一的 `100 bpm` 上限，也可能触发个体异常。

## 7. EWMA 与 CUSUM 趋势检测

### 7.1 EWMA

系统使用指数加权移动平均突出近期数据：

```text
EWMA_t = 0.35 * x_t + 0.65 * EWMA_(t-1)
```

### 7.2 CUSUM

系统同时累计相对个人中心的连续偏差：

```text
positive_t = max(0, positive_(t-1) + z_t - 0.5)
negative_t = max(0, negative_(t-1) - z_t - 0.5)
```

只有 EWMA 和 CUSUM 同时超过阈值时才判定趋势异常，减少单次波动导致的误报。

趋势分数：

- 普通持续趋势：8 分。
- 明显持续趋势：12 分。

输出会说明趋势方向和两个检测量：

```text
心率出现持续上升趋势（EWMA 偏离 2.1，CUSUM 6.4）
```

## 8. 多指标联合异常

### 8.1 日级特征向量

系统按天聚合每个指标最后一次有效记录，建立历史向量：

```text
[收缩压, 舒张压, 心率, 血糖]
```

缺失指标以对应个人中位数填充，即标准化后的零值。

### 8.2 收缩协方差

个人数据量通常较少，普通协方差矩阵可能不可逆。系统对协方差进行收缩并加入
岭项：

```text
非对角元素 *= 0.75
对角元素 = 0.75 * variance + 0.25 + 0.10
```

然后计算马氏距离：

```text
D² = (x - μ)ᵀ Σ⁻¹ (x - μ)
```

如果矩阵仍不可逆，则回退到对角马氏距离，即各特征鲁棒 Z 分数平方和。

### 8.3 判定阈值

系统使用卡方分布近似阈值：

| 维度 | 95% 阈值 | 99% 阈值 |
|---:|---:|---:|
| 2 | 5.99 | 9.21 |
| 3 | 7.81 | 11.34 |
| 4 | 9.49 | 13.28 |

- 超过 95% 阈值：增加 10 分。
- 超过 99% 阈值：增加 18 分。

该层可以发现“每项只略有变化，但组合方式从未在用户历史中出现”的情况。

## 9. 数据可信度

个体统计分数根据数据来源和样本量修正：

| 数据来源 | 来源系数 |
|---|---:|
| Health Connect、医疗设备 | 0.98 |
| 智能手环、手表、可穿戴设备 | 0.93 |
| 手动录入 | 0.82 |
| 未标记来源 | 0.74 |

样本量系数：

```text
sampleConfidence = min(1, 0.65 + 同类样本数 / 40)
confidence = sourceConfidence * sampleConfidence
```

最终置信系数限制在 `0.60～1.00`。

注意：可信度只修正个体统计模型分数，不会降低医学红线分数。

## 10. 分数融合与风险等级

当前实现采用有上限的可解释加法融合：

```text
总分 =
  医学规则分数
  + 个体模型分数（最高 45）
  + 近 24 小时关联指标分数
  + 未完成服药提醒 10 分
```

最终分数限制在 `0～100`。

风险等级：

| 条件 | 等级 |
|---|---|
| 总分 `>= 70` 或本次医学/个体分数 `>= 60` | `high` |
| 总分 `>= 35`、本次记录触发异常或个体模型触发 | `elevated` |
| 其他 | `normal` |

`high` 事件会沿用现有逻辑创建 `prepared` 状态的 SOS 预案，但不会自动拨号或发送通知。

## 11. 冷启动与降级

系统使用以下降级策略：

1. 同类历史不足 7 条：不运行该指标的个体基线和趋势检测。
2. 多指标历史不足 7 天：不运行联合异常检测。
3. 协方差矩阵不可逆：回退到对角马氏距离。
4. 个体模型无法运行：仍保留完整医学规则、提醒和 SOS 逻辑。
5. 来源未知或样本较少：降低个体模型置信系数，不影响医学红线。

因此，新用户不会因为缺少历史数据而无法获得基本风险提示。

## 12. 前端表现

现有 Flutter 风险弹窗会自动展示后端返回的 `reasons`，无需新增接口。

可能出现的解释包括：

```text
本次录入：血压高于建议范围（145/92 mmHg）
个体基线：收缩压为 136 mmHg，个人基线约 111～123 mmHg，偏离 3.6 MAD
个体基线：心率出现持续上升趋势（EWMA 偏离 2.1，CUSUM 6.4）
多指标联合异常：血压、心率或血糖的组合偏离个人历史模式（收缩马氏距离²=10.8）
数据可信度：智能手环/可穿戴设备，个体模型置信系数 93%（算法 hybrid-risk-v1）
```

主要测试：

```text

├── AdaptiveRiskAnalyzerTest.java
└── RiskEngineServiceTest.java
```

已覆盖：

- 医学参考范围内、但显著偏离个人基线的心率。
- 稳定个人数据不触发风险。
- 血压、心率、血糖联合偏离。

## 14. 演示建议

建议准备以下数据：

1. 先为测试用户写入 14 天 `68～74 bpm` 的上午静息心率。
2. 本次写入 `96 bpm`，来源设置为 `smart_band`。
3. 医学固定规则不会触发，因为心率没有超过 `100 bpm`。
4. 个体模型计算出明显 MAD 偏离，产生 `elevated` 事件。
5. Flutter 收到 SSE 后展示个人基线、偏离程度和可信度。

该场景可以直接说明固定阈值与个体化算法的差异。

## 15. 已知边界

- 当前时间分段是规则分桶，不是完整昼夜节律模型。
- 当前没有接入运动状态、睡眠状态和设备离腕状态。
- 当前分数用于健康关注度排序，没有经过临床数据校准。
- 当前模型按请求即时计算，数据量增大后可增加 Redis 基线缓存。
- 当前只提供可解释异常检测，不输出疾病名称或诊断结论。

后续可以在保持医学安全规则的前提下增加运动上下文、用户反馈校准和风险沙盘。
